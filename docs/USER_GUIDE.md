# MSF-HSAT detailed user guide

See [the repository README](../README.md) for the current project layout,
installation, verified results, and GitHub instructions. The sections below
describe the original single-file delivery; statements about its authoring
environment are historical, not the current local verification status.

**A single-file, local PyTorch research implementation for 3D primary lung-tumor segmentation.**

The program predicts the expert-defined primary gross tumor volume, usually **GTV-1**, in a CT scan. It combines a residual encoder, multiscale convolutions, compact transformer attention, acquisition- and decoder-conditioned 3D wavelet skip refinement, and adaptive decoder fusion.

The proposed name used in code is **MSF-HSAT**. This is a candidate research architecture. Its accuracy, clinical usefulness, novelty, and publication value have **not** been established by this delivery. You must train it, audit its predictions, compare strong baselines fairly, and validate the hypothesis experimentally.

The core implementation is a single Python file. The repository also maintains
dependency declarations, tests, CI, and documentation:

| File | Purpose |
|---|---|
| `lung_ct_segmentation.py` | Data preparation, splitting, both 3D models, training/resume, inference, metrics, plots, offline reports, ablations, and self-tests. |
| `README.md` | Installation, beginner explanations, exact commands, implementation choices, research protocol, and limitations. |

Experiment artifacts mentioned below are generated by commands. No notebook or
extra model module is required. Use the repository requirements.txt for dependencies.

**Verification at delivery:** Python compilation and 16 available mathematical/utility tests passed. Five test groups requiring PyTorch or imaging packages could not run in the authoring environment. No GPU run, real CT training run, or real-data DICOM conversion was performed here. See the verification section before interpreting this as a tested training release.

## 1. What you are building, in beginner language

A CT scan is a stack of spatial slices forming a three-dimensional image. Each voxel has a physical size and a value related to X-ray attenuation. A segmentation mask is a matching grid of zeros and ones: one means that voxel belongs to the annotated primary tumor.

The model takes a **small 3D patch**, predicts a value for every voxel, and learns by comparing those predictions with the expert mask. At prediction time it slides over the entire scan. Overlapping predictions are blended, mapped back to the original CT geometry, and exported as both continuous probabilities and a binary mask.

Your dataset may occupy hundreds of gigabytes, while your GPU might have only a few gigabytes of VRAM. Those are separate problems. This implementation stores prepared scans on disk and sends one minibatch of patches to the GPU at a time. It does not try to load the entire dataset onto the GPU or into RAM.

The final output describes **membership in the annotated primary target**. It does not establish whether an arbitrary patient has cancer, classify benign versus malignant nodules, segment every malignant focus, or predict survival. Apparent false positives are measured against the provided annotation scope.

| CPU | Explicit debugging and mathematical tests. No silent large CPU fallback. |
| Other accelerator backends | Not implemented; MPS/DirectML/Intel XPU are not advertised as working. |
| Native-grid prediction/evaluation | Implemented through physical-coordinate resampling. |
| Validation-only threshold selection | Implemented as `select-threshold`; test/external inputs rejected. |
| Extensive figures/offline HTML | 54 catalogued families with created/skipped/failed provenance records. Availability depends on saved artifacts. |
| Multi-model paired comparison | Implemented for compatible completed evaluation folders. |
| Multi-checkpoint ensemble uncertainty | Not implemented; explicitly skipped. Several model results do not constitute an ensemble. |
| Automated acquisition stress study | Not implemented; explicitly skipped. Training noise is not a stress-study result. |
| MRF, texture, intensity-only course baselines | Not implemented. They are optional future experiments, not mislabeled morphology. |
| Official nnU-Net/Swin UNETR | Not integrated. `baseline3d` must never be described as an official reproduction. |

Missing optional analyses are not filled with fake numbers. Missing core dependencies produce an actionable error. The program never downloads patient data, uploads scans, installs packages, or starts training simply because it was imported.

## 4. Install on a laptop

Use a dedicated virtual environment. A practical target is Python **3.11 or 3.12** with a PyTorch build compatible with your OS, NVIDIA driver, and GPU. This is a recommended setup, not a combination that was GPU-tested for this delivery.

### Windows PowerShell

```powershell

.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

If your machine has Python 3.12 instead, replace `-3.11` with `-3.12`. If activation is restricted, you can invoke `.\.venv\Scripts\python.exe` directly in place of `python`.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

Open the [official PyTorch installation selector](https://pytorch.org/get-started/locally/). Choose your actual OS and accelerator build and run the command it supplies inside the virtual environment. Do not copy a CUDA-wheel URL from an unrelated tutorial. A system CUDA toolkit version alone does not prove your Python environment contains a CUDA-enabled torch wheel.

The code uses `torch.amp.GradScaler`, `torch.amp.autocast`, `scaled_dot_product_attention`, checkpointing with `use_reentrant=False`, and `torch.load(..., weights_only=True)`. Use a modern release exposing these APIs; **PyTorch 2.3 or newer is the intended API floor**, but the particular release you install still needs the supplied tests.

## 5. Verify GPU access before preparing a long run

```bash
python lung_ct_segmentation.py doctor --path . --output doctor.json
```

Look for `cuda_available: true`, the expected GPU name, and a reasonable VRAM value. The JSON also records the CUDA version against which torch was built. The full training process checks the actual backend again.

If CUDA is absent, fix the environment first. `train --device auto` fails rather than quietly starting a huge CPU job. For a deliberately small CPU debugging experiment, specify `--device cpu --precision fp32` and a small custom patch.

Preflight is different from doctor. Doctor inspects the environment; preflight constructs the actual model and runs a synthetic forward pass, backward pass, and AdamW update so optimizer-state allocation is included. It is still not a real-data speed benchmark and does not guarantee every later allocation will fit.

## 6. Dataset and target eligibility

Use the [TCIA NSCLC-Radiomics collection](https://www.cancerimagingarchive.net/collection/nsclc-radiomics/) and its [version/description notes](https://wiki.cancerimagingarchive.net/display/Public/NSCLC-Radiomics). Preserve the original dataset unchanged.

The collection's nominal 422 subjects are **not** hard-coded as 422 eligible primary-target cases. The usable cohort is determined from your actual corrected source and QC records.

Known issues reflected in this workflow:

| Case/issue | Policy |
|---|---|
| `LUNG1-128` | Documented postoperative case without GTV-1. Excluded when that patient ID is retained. Do not disguise it as an ordinary confirmed-negative primary-tumor case. |
| `LUNG1-014`, `LUNG1-021`, `LUNG1-085` | Documented missing slices. The strict raw route detects nonuniform positions and excludes any series with geometry gaps, including gaps outside the GTV. |
| Corrected releases | Record what you downloaded with mandatory `--release`; the program does not infer a release from a folder name. |
| Missing ROI | Record an exclusion with available exact ROI names. Do not union every RTSTRUCT structure. |
| Empty reference | Positive cases are rejected. Explicit verified negative and unlabeled states remain different. |
| Different CT series | Associate RTSTRUCT through actual referenced UIDs and geometry. |

The conservative missing-slice policy can reduce eligibility relative to another paper. Report this transparently; do not compare cohort counts as though eligibility policies were identical. If an expert prepares a verified gap-aware conversion externally, it can enter through the paired route with appropriate provenance, but this program does not repair unknown gaps automatically.

The source collection lists **CC BY-NC 3.0** licensing. Check its current terms, citation requirements, and any separate related-file licenses before redistribution or commercial use. This delivery does not grant additional rights to the dataset or source-paper implementations.

If your identifiers were changed during de-identification, the literal `LUNG1-128` check cannot recognize the renamed case. Maintain an external identity/eligibility audit and exclude known exceptions explicitly before creating your cohort.

## 7. Route A: paired research NIfTI volumes

The simplest route is a CSV with explicit identities and image/mask paths:

```csv
case_id,patient_id,image,mask,annotation_status
LUNG1-001,LUNG1-001,images/LUNG1-001.nii.gz,masks/LUNG1-001.nii.gz,positive
LUNG1-002,LUNG1-002,images/LUNG1-002.nii.gz,masks/LUNG1-002.nii.gz,positive
```

Each row needs `case_id`, `patient_id`, and `image`. A labeled row also needs `mask`. Paths can be absolute or relative to the CSV file's parent directory. Quote CSV fields containing commas. Paths with spaces work when the CLI path is quoted.

| Column | Meaning |
|---|---|
| `case_id` | Unique safe cache/output name: letters, digits, dot, dash, underscore; maximum 120 characters. |
| `patient_id` | Groups every series/session/view of one patient for splitting. Never assign a new patient ID per slice. |
| `image` | Scalar 3D `.nii`/`.nii.gz` CT in HU, not JPEGs, normalized screenshots, or prewindowed 8-bit data. |
| `mask` | Matching scalar binary mask, values exactly 0/1; blank only for unlabeled cases. |
| `annotation_status` | `positive`, `negative`, or `unlabeled`. Default is positive if a mask is supplied, otherwise unlabeled. |
| `source_id` | Optional source identity hint in fast stat mode. SHA-256 image identity takes precedence when enabled. |

The code checks dimensions, origin, spacing, direction, labels, and emptiness. It **rejects** mismatched CT/reference grids. It does not copy headers to make a misregistered mask look aligned. Confirm conversion in an independent imaging viewer before training.

Prepare:

```bash
python lung_ct_segmentation.py prepare --input-csv "data/cases.csv" --output "prepared/nsclc" --spacing 2.5 1 1 --roi GTV-1 --release "your-corrected-TCIA-release" --qc-cases 12
```

For exact filename matching without a CSV:

```bash
python lung_ct_segmentation.py prepare --images-dir "data/images" --masks-dir "data/masks" --output "prepared/nsclc" --release "your-corrected-TCIA-release"
```

The directory route expects the same stem in both directories, such as `A.nii.gz` and `A.nii.gz`, and assumes **one patient per filename**. It does not strip `_0000`, guess suffixes, or infer that two differently named series belong to one patient. Use CSV for those situations.

An explicitly verified negative row must supply a real, physically aligned empty mask and `annotation_status=negative`. This is not a way to convert missing annotations into negatives. The intended NSCLC primary-target cohort is generally positive; introducing negatives changes the study definition.

## 8. Route B: original CT DICOM plus RTSTRUCT

Install the optional raw-route packages, then point to a tree containing CT slices and their RTSTRUCT objects:

```bash
python lung_ct_segmentation.py prepare --dicom-root "D:/TCIA/NSCLC-Radiomics" --output "D:/prepared/nsclc" --roi GTV-1 --spacing 2.5 1 1 --release "your-corrected-TCIA-release" --qc-cases 12
```

Folder nesting is not used as proof of association. The scanner groups CT slices by `SeriesInstanceUID`, reads RTSTRUCT references, requires exactly one matching CT series, validates frame and SOP references, and selects the **exact** configured ROI name.

Supported raw geometry and contours:

- Scalar, single-frame CT images with consistent dimensions, spacing, parallel orthonormal orientation, and uniform geometric slice positions.
- Geometrically sorted planes, unique SOP/plane positions, no missing-plane gaps, no lateral displacement/gantry tilt.
- `CLOSED_PLANAR` target contours lying on the selected planes and inside the CT field of view.
- Ordinary nested planar contours rasterized together by RT-utils; the local synthetic integration test includes a hole and non-square slices.
- Rejection of malformed/degenerate polygons, repeated keyhole vertices, self-intersection, open contours, and `CLOSEDPLANAR_XOR` encoding.

The route isolates only the selected CT files in a temporary folder for RT-utils, using hard links where possible and copying only if necessary. It checks RT-utils' actual loaded SOP order and transposes its rows/columns/slices mask into z/y/x deliberately.

SimpleITK/GDCM applies the DICOM rescale slope/intercept when reading the CT. The program does **not** apply a second HU conversion. Slice thickness is retained separately from measured center-to-center slice spacing.

Unsupported input is excluded with a visible reason. Enhanced multiframe CT and DICOM SEG are not converted. Multiple RTSTRUCT objects describing the same CT can create ambiguous duplicate case IDs; curate which intended annotation to use rather than silently choosing the first file.

Because this raw route was not executed in the authoring environment, run the full self-test locally and visually inspect real-case overlays in axial, coronal, and sagittal views before trusting your cache.

## 9. Geometry, working grids, and cache behavior

| Representation | Axis convention |
|---|---|
| NumPy volume | `D,H,W` = `z,y,x` |
| Network tensor | `B,C,D,H,W` |
| SimpleITK size/spacing/index | `x,y,z` |
| Physical coordinates | LPS convention supplied by SimpleITK, millimeters |
| Conditioning stages | E2 stride `(2,4,4)`; E3 stride `(4,8,8)` relative to working input |

Preparation records the complete original grid: shape, spacing, origin, and direction. It reorients toward LPS using SimpleITK, constructs an explicit working grid, resamples CT continuously and masks with nearest neighbors, and records that working grid too. Oblique orthonormal directions retain their physical direction; merely displaying three array planes does not justify unsupported left/right orientation letters.

**No tumor-based crop is used.** The prepared field of view is the entire resampled CT. Training can sample around known training foreground; inference always covers the complete prepared volume. The cache records zero crop offset. This trades extra background computation for a clear no-reference-crop inference contract.

Working spacing `(2.5,1,1)` mm is an **illustrative explicit default**, not an optimum measured from this collection. Choose and prerecord it from training-only planning and resource checks. The program does not automatically learn target spacing from the whole cohort or use the test set to choose it.

For a source dimension `n`, the target size is chosen to cover center coordinates approximately as `ceil((n-1)*old_spacing/new_spacing)+1`. Predictions are resampled back through physical coordinates using the stored grids. A binary mask is thresholded **after native-grid probability resampling**.

The cache contains:

| File in each case directory | Purpose |
|---|---|
| `hu.npy` | Float32 working HU volume, memory-mappable. |
| `mask.npy` | UInt8 working reference, labeled cases only. |
| `boundary.npy` | UInt8 full-volume physical boundary band. |
| `native_mask.npy` | Original-grid reference for physical evaluation. |
| `fg_indices.npy` | At most 100,000 deterministic sampled working foreground indices for patch sampling. |
| `metadata.json` | All grids, identities, acquisition fields, eligibility, target and preprocessing. |
| `complete.json` | Fingerprint and expected file sizes, written only after successful preparation. |

Prepared arrays use more disk space than compressed NIfTI but support efficient random patches without decompressing an entire `.nii.gz` on every sample. Approximate working-array storage is `4*N_working` bytes for HU plus `N_working` each for mask and boundary, plus `N_native` for native labels. Headers, foreground coordinates, QC images, and output predictions add overhead. These formulas are planning estimates; the actual cache record stores file sizes.

Only one case is prepared at a time. Full-volume resampling and distance transforms still require RAM proportional to that **single case**. A very large individual CT can exceed laptop RAM despite cohort-level bounded loading. The code checks destination free space before case writes and never erases old caches automatically.

Cache entries are written in staging directories and atomically renamed on completion. Interrupted incomplete directories are not mistaken for complete arrays. Relevant source identities, size/time metadata, preprocessing, target and cache schema are fingerprinted. Default SHA-256 hashing adds an initial sequential read but helps identify copied inputs. `--source-hash stat` is faster and weaker: it cannot prove two differently stored images are distinct patients and cannot detect every content-preserving/mutated-copy scenario.

Rerunning `prepare` with identical settings reuses valid entries. Changing settings or the cohort requires a **new output directory**. A changed cohort is saved as a candidate manifest while the original manifest remains intact, protecting existing split/checkpoint identities. Completion validation checks identities and file sizes, not a full checksum of every cached array on every training patch; use appropriate storage integrity practices.

## 10. Inspect preparation before splitting

Read `prepared/nsclc/qc.csv`, `qc.json`, `manifest.csv`, and the selected images under `qc/`. Verify:

1. The primary tumor is actually selected rather than lung, heart, nodes, or another ROI.
2. Contours align on all three planes.
3. Reference voxels remain after resampling.
4. No duplicate/missing geometry was silently accepted.
5. HU ranges and working resolution make sense.
6. Case IDs and patient groups reflect the actual identities.

`--qc-cases` limits example images, not the number of converted cases. Numeric and geometry QC runs on every case. A displayed axial/coronal/sagittal panel is a useful check, not proof that every contour in a dataset is correct. The `qc.csv` exclusions define the actual cohort; include their counts and policy in your eventual paper.

## 11. Patient splits and development cross-validation

Create the split once, **before extracting patches**:

```bash
python lung_ct_segmentation.py split --manifest "prepared/nsclc/manifest.json" --output "splits/main.json" --seed 42 --test-fraction 0.2 --val-fraction 0.2
```

Fractions apply to independent patient/source groups with rounding and minimum group counts. They do not promise exact patient or case counts. All cases of a patient and matching source identities form connected groups. The program validates disjoint patient IDs, source identities and case IDs.

Rerunning `split` on an existing output validates and preserves it; it does not silently generate new partitions because a seed flag changed. The immutable split has a manifest fingerprint and its own fingerprint. Do not edit it manually to move difficult test patients into training.

For five development folds with the same locked test set:

```bash
python lung_ct_segmentation.py split --manifest "prepared/nsclc/manifest.json" --output "splits/fold0.json" --seed 42 --test-fraction 0.2 --folds 5 --fold 0
python lung_ct_segmentation.py split --manifest "prepared/nsclc/manifest.json" --output "splits/fold1.json" --seed 42 --test-fraction 0.2 --folds 5 --fold 1
```

Repeat for fold indices 2–4. The same seed and source manifest preserve the held-out test groups while rotating the development validation groups. Each train command trains **one fold**, not all folds automatically.

Cross-validation thresholding and final checkpoint selection require a prespecified protocol. The supplied `select-threshold` command targets one checkpoint's explicit validation evaluation, not a complete out-of-fold calibration/ensemble framework. Do not pretend five independent fold tests are one untouched test experiment after repeated tuning.

## 12. Self-tests and what their exit codes mean

```bash
python lung_ct_segmentation.py self-test --output self_test.json
```

Tests cover window arithmetic, invalid labels, physical axes, an independent NumPy Haar reference, patch padding/randomness, sliding-window coverage, anisotropic distances, full-volume boundary bands, augmentation, patient/source grouping, descriptor normalization, calibration/ROC arithmetic, patient bootstrap units, cache integrity, real white PNG files, empty-report honesty, and dependency-dependent imaging/model paths.

The PyTorch tests, when installed, exercise Haar on even/odd/singleton sizes, autograd, window partition/reassembly, padded-key masking, both 3D forward passes, a finite backward pass, gate bounds, source-weight normalization, kappa-zero identity, main/auxiliary prediction agreement, safe checkpoint loading, and prediction agreement after reload.

The raw-route synthetic test builds a small CT series with known HU slope/intercept and a non-square target mask with a hole, converts CT+RTSTRUCT back, and measures the actual overlap and geometry. It contains **no patient data**.

| Exit code | Meaning |
|---|---|
| 0 | All tests passed, or `--available-only` was explicitly used and the JSON still marks missing groups as partial. |
| 1 | At least one real test failed. Read its traceback in the JSON. |
| 2 | No executed test failed, but dependencies prevented complete verification. |

To check independent utilities before installing optional packages:

```bash
python lung_ct_segmentation.py self-test --available-only --output self_test_available.json
```

`PARTIAL` is not equivalent to full verification. A perfect toy mask does not establish real-data model performance.

## 13. Two CT windows from one acquisition

After any HU intensity augmentation, the code constructs:

```text
lung = (clip(HU, -1000, 400) + 1000) / 1400
soft = (clip(HU, -160, 240) + 160) / 400
```

Both channels are aligned views of the **same** CT. One emphasizes broad lung context; the other uses a narrower soft-tissue range. They are not two independent modalities and do not turn CT into a visible/infrared multispectral acquisition.

`--input-channels 1` uses only the lung window. This changes the input layer and is an actual one-window ablation. Validation/test normalization is fixed by these formulas, not refit from their labels.

## 14. Architecture and exact reference shapes

With the reference preset, a patch is `B,2,64,192,192`:

| Stage | Channels | D,H,W | Operation |
|---|---:|---|---|
| Input | 2 | 64,192,192 | Two derived CT windows |
| E0 | 24 | 64,192,192 | Two residual blocks; default early kernels 1×3×3 |
| E1 | 48 | 64,96,96 | Stride 1,2,2; two residual blocks |
| E2 | 96 | 32,48,48 | Stride 2,2,2; residual plus multiscale block |
| E3 | 192 | 16,24,24 | Stride 2,2,2; residual plus multiscale block |
| E4 | 256 | 8,12,12 | Stride 2,2,2; two residual blocks |
| T | 256 | 8,12,12 | Two pre-norm transformer blocks |
| E3 wavelet bands | 192 each | 8,12,12 | LLL plus seven details |
| E2 wavelet bands | 96 each | 16,24,24 | LLL plus seven details |
| D3 | 192 | 16,24,24 | T/context, conditioned E3, aligned E2 |
| D2 | 96 | 32,48,48 | D3/context, conditioned E2, aligned E1 |
| D1 | 48 | 64,96,96 | D2, E1, aligned E0 |
| D0 | 24 | 64,192,192 | Upsampled D1 concatenated with E0, refinement |
| Main head | 1 | 64,192,192 | Raw foreground logits |

Shapes scale with presets and custom patch dimensions. Strided convolutions can round odd sizes upward; interpolation aligns actual tensors explicitly. The reference table is not a statement that every dataset volume has these dimensions.

The computation is acyclic: the deeper decoder produces U3 before E3's skip is conditioned; D3 then produces U2 before E2's skip is conditioned. No gate needs the decoder output it is currently constructing, and no inference gate consumes a reference mask.

### Residual CNNs and multiscale context

A convolution learns local filters shared across a volume. A residual block learns a change to a direct feature path. GroupNorm avoids depending on large batches, useful when a 3D laptop minibatch is one.

At E2/E3, channels are reduced to about C/2, processed by three parallel depthwise 3D convolutions with dilation 1, 2, and 3, concatenated, projected to C, and added to the original feature. Different dilation gives different receptive fields without tripling the full dense-convolution cost.

Early kernels default to 1×3×3 to limit immediate through-plane mixing; E1 still uses the explicit anisotropic stride `(1,2,2)`. `--isotropic-early` changes the early kernels to 3×3×3, not the stride schedule.

### Compact transformer

E4 becomes `B,N,C` tokens. For the reference geometry, N is 8×12×12 = **1,152**. The model adds fixed separable 3D sin/cos coordinates and applies two pre-normalized attention/FFN blocks, eight heads, and an FFN expansion of two. It uses PyTorch scaled-dot-product attention.

Full attention is restricted by a 4,096-token guard at this stage. There is no all-voxel attention over an entire CT. With sliding windows, “global” means global **inside the current patch representation**.

The reference score matrix has N² = 1,327,104 entries per head. Eight FP16 score matrices alone would be about 20.25 MiB; that is **not total training VRAM**. Projections, gradients, all feature maps, optimizer state, wavelet branches and temporary workspaces also consume memory.

## 15. Haar analysis and the proposed conditioned skips

The fixed orthonormal 1D filters are `L=[1,1]/sqrt(2)` and `H=[1,-1]/sqrt(2)`, using the cross-correlation sign convention. Their separable 3D products give:

`LLL, LLH, LHL, LHH, HLL, HLH, HHL, HHH`.

Letters correspond to **z, y, x**, in that order. LLL is a coarse learned-feature component; the seven others describe directional feature changes. They are not direct physical tissue spectra or an independent scanner-energy measurement.

Each spatial dimension halves after one analysis level. All eight bands are retained, so the transform does not reduce total padded coefficient count. Right/back/bottom odd edges use replicate padding, and synthesis crops to the original dimensions. Energy preservation is tested relative to the padded tensor. The unmodified transform pair can reconstruct its input; the learned module intentionally changes coefficients and is not described as lossless.

LLL passes through residual window attention with default windows `(4,6,6)` and four heads. Windows pad as needed, mask invalid keys, zero padded query outputs, and reassemble/crop correctly.

Each detail band uses:

```text
R_b = H_b + delta_b(H_b)
g_b = sigmoid(G_b(concat(abs(H_b), pooled_projected_U_i, embedded_q_i)))
H_tilde_b = g_b * R_b
```

`delta_b` contains depthwise convolution, GroupNorm, SiLU and pointwise convolution, and returns **only the correction**. There is one identity, not a double-counted H_b.

The acquisition descriptor is:

```text
q_i = concat(log(native_spacing), log(target_spacing/native_spacing), log(stage_spacing_i))
```

Each term has three axes. Native spacing is retained after resampling. For permuted input axes, the conditioning version uses the native acquisition spacings reordered into the oriented working-axis convention; original native-grid metadata remain preserved separately. Stage spacing reflects actual accumulated strides. Units are fixed to millimeters before taking logs.

Statistics are computed **only from training patients**, first averaging a patient's multiple series. Near-constant descriptor columns receive unit standard deviation, avoiding division by zero. E2/E3 have separate means with the appropriate stage-spacing shift.

After inverse transform:

```text
S_i = E_i + sigmoid(kappa_logit_i) * Conv1x1x1(reconstructed - E_i)
```

The bounded coefficient starts near 0.1, preserving a strong direct path. Setting it mathematically to zero yields the original skip, which the local model self-test checks. A gate value is an internal learned weight, not a calibrated probability of image quality.

Native spacing is only an acquisition **proxy**. It does not encode complete reconstruction quality, motion, dose, scanner hardware, or all protocol differences. Demonstrate the value of conditioning with genuine constant/shuffled controls and acquisition subgroups rather than asserting it from the formula.

## 16. Decoder fusion, outputs, and losses

The proposed decoder aligns three sources at each of D3/D2/D1. Each source is projected to the same C. Their sum is globally pooled and an MLP produces M×C logits. Softmax is applied across the **source axis independently per channel**. A weighted sum and residual refinement produce the decoder feature.

This is source/channel weighting, not a per-voxel spatial-attention map. Directional skip gates are spatially varying; the decoder source weights are spatially shared per channel.

The baseline uses ordinary two-source residual skip fusion with concatenation and projection. The hybrid architecture with `--no-adaptive-fusion` keeps its three sources but concatenates them, so an adaptive-fusion ablation changes weighting while retaining sources.

Main output is one raw logit per voxel. Training additionally collects D1/D2 auxiliary segmentation logits and D0 boundary logits when enabled. Evaluation can collect or omit auxiliary outputs without altering the main prediction.

The default objective is:

```text
L_main = foreground_soft_Dice_loss + BCEWithLogitsLoss
L_total = L_main + lambda_ds*(0.5*L_D1 + 0.25*L_D2) + lambda_boundary*L_boundary
lambda_ds = 1.0
lambda_boundary = 0.1
```

Dice reductions are per example over channel/spatial axes, then averaged across the batch. Sensitive reductions use FP32. BCE consumes logits directly, avoiding a duplicate sigmoid. Auxiliary logits are interpolated to the full patch target grid; tiny targets are not discarded by nearest-neighbor label downsampling.

The boundary target is a two-sided physical distance band, default width 2 mm, built on the **whole working volume** before patches are cut. Distance is measured from the foreground boundary voxel centers defined by 6-neighbor erosion; those surface voxels remain included even when through-plane spacing exceeds 2 mm. Patch edges therefore do not manufacture new target surfaces. Geometric augmentation transforms this precomputed band with the mask; a scale augmentation scales the represented band rather than recomputing an exactly fixed-width band afterward. This is an explicit target convention.

All components are logged separately before weighting. Nonfinite losses or gradients stop with diagnostics. The code never changes NaNs into zeros and continues as though training succeeded.

Example:

```bash

```

AMP `auto` chooses BF16 when CUDA reports support, otherwise FP16 on CUDA, otherwise FP32 for explicitly requested CPU debugging. FP16 uses GradScaler; BF16 does not require gradient scaling. You can request `--precision fp16`, `bf16`, or `fp32`, subject to device checks.

Additional memory controls:

- `--gradient-checkpointing` recomputes encoder/bottleneck activations during backward, trading speed for memory. It is not a promise that every module is checkpointed.
- `--patch 24 80 80` overrides the candidate patch; use a new run and preflight.
- `--batch-size 1` limits instantaneous patch count.
- `--accumulation 4` combines microbatch gradients before an update; it does not change batch-dependent layers into large-batch training.
- `--accumulator-dir "D:/ct_accumulators"` moves full-volume blending arrays to temporary disk-backed storage. Final per-case probability arrays and physical image operations still use RAM.

The program does not retry indefinitely after OOM or silently shrink patches mid-training. A new architecture/patch/batch recipe is a separately labeled run. Reference E4 attention may fit while earlier full-resolution feature maps or optimizer allocations still cause OOM.

## 18. Patch loading, augmentation, and deterministic sampling

The dataset maintains at most two open case entries per worker using memory maps. It returns CPU tensors; workers never allocate CUDA memory. Main-process transfers use pinned memory/nonblocking only for CUDA.

Default `--workers 0` is conservative and Windows-safe. Positive worker counts use bounded prefetching and recreate workers each epoch. Persistent workers are intentionally disabled to avoid stale epoch copies. The script uses `freeze_support()` and a guarded main entry point.

Each sample's randomness is indexed by seed, epoch and sample number, using NumPy `SeedSequence`; it does not depend on Python's process-randomized `hash()`. Sampling chooses a training case and, with default probability 0.5, a stored foreground coordinate; otherwise it samples context uniformly. Uniform context sampling can still overlap tumor. Foreground oversampling changes the training patch distribution and must not be confused with full-volume evaluation prevalence.

Augmentation jointly transforms HU, mask and boundary: modest ±10° in-plane rotation, scale 0.9–1.1, in-plane flips, HU perturbation, Gaussian noise, and occasional in-plane blur. Both input windows are generated afterward, keeping their HU relation coherent. There is no default superior/inferior flip and no simulated through-plane resolution-change experiment. Validation/test inputs are not randomly augmented.

`--no-augmentation` disables these transformations. `--deterministic` requests deterministic torch algorithms and errors if an operation cannot comply. Reproducibility across different torch versions, kernels and hardware is not promised to be bitwise exact.

## 19. Training budgets and actual optimizer updates

Defaults are AdamW, learning rate 1e-4, weight decay 1e-4, up to 200 epochs, 100 microbatches/epoch, accumulation two, five warmup epochs, and a cosine decay with a 1% learning-rate floor. These are starting recipes, not an experimentally optimal NSCLC budget.

`--steps-per-epoch` counts **microbatches**. The maximum planned optimizer updates are:

```text
max_epochs * ceil(steps_per_epoch / accumulation)
```

The final partial accumulation group is normalized by its actual number of microbatches, not blindly divided by the full accumulation factor. Gradients are unscaled before clipping. The schedule advances with successful optimizer updates, not every microbatch.

Full-volume validation runs every `--val-every` epochs and at the final configured epoch. Default checkpoint selection uses **mean patient-level validation Dice**, after averaging multiple case values within a patient. A case with technical validation failure prevents checkpoint selection and stops the run rather than disappearing from the mean. A complete predicted miss is a valid zero-Dice outcome and stays in the score.

Patch loss and complete-volume validation Dice have different sampling and measurement protocols. They are plotted with distinct names. There is no misleading “training accuracy” computed from a background-dominated voxel total.

Optional `--early-stopping-checks N` counts non-improving **validation checks**, not epochs. Zero disables early stopping. A twelve-epoch smoke experiment is useful for debugging but is not automatically an adequate publication budget.

## 22. Checkpoints, interruption, and resumption

Checkpoints are atomic `checkpoints/last.pt` and `checkpoints/best.pt` files. They contain plain state dictionaries and safe types: model configuration/state, optimizer, scheduler, AMP scaler, completed epochs, optimizer steps, best criterion, history, RNG states, acquisition statistics, threshold, manifest/split fingerprints, source identities, and scientific training settings.

Loading uses `weights_only=True`; the program does not silently switch to unrestricted pickle loading for a downloaded checkpoint. Use checkpoints whose provenance you understand.

Resume:

```bash
python lung_ct_segmentation.py train --manifest "prepared/nsclc/manifest.json" --splits "splits/main.json" --run "runs/hybrid_seed42" --resume "runs/hybrid_seed42/checkpoints/last.pt"
```

The saved scientific/optimization settings are restored. Explicit conflicting CLI changes are rejected. You cannot change patch dimensions, architecture, learning-rate budget or normalization halfway through a resumed experiment and call it the same run. Use the original run directory. Device selection may be supplied explicitly, but the recorded precision must be supported and RNG device-count constraints must match.

**Recovery policy: replay the unfinished epoch from the last completed epoch boundary.** An initial epoch-zero checkpoint exists before training begins. Ctrl+C records the interruption and points to `last.pt`. It does not write a partial-epoch model and pretend it can exactly replay worker queues. Other failures also preserve the last complete checkpoint; read `failure.json`.

This policy limits checkpoint write cost and avoids claiming exact batch-level replay with prefetched workers. Work since the last completed epoch can be lost. `best.pt` exists after successful validation improves the criterion; before the first successful validation there may only be `last.pt`.

## 24. What sliding-window inference actually does

For each working volume, the program constructs a complete grid of patch starts. A final start is added at each axis end when stride would otherwise miss it. Smaller volumes are padded on the high side. Each patch produces **main logits only** under evaluation/inference mode.

Patches use Gaussian importance with sigma approximately patch/8 and a minimum weight of 1e-4. Weighted logits accumulate on CPU, optionally in disk-backed arrays. Every voxel's weight must be positive. The sum is divided by the weights, followed by a single sigmoid. This is logit blending, not averaging already-thresholded masks.

The continuous working probability is resampled to the original CT grid with linear interpolation. The recorded threshold is applied there. Native probability and prediction are exported as `.nii.gz` with the original spacing, origin, direction and shape.

Default overlap is 0.5. Increasing overlap increases runtime and may change predictions, so record it and keep it consistent in comparisons. There is no test-time augmentation, learned localization crop, whole-scan global attention, largest-component filtering, or hidden postprocessing in this implementation. Postprocessing is explicitly `none`.

## 25. Physical metrics and empty cases

All final metrics use **native-grid complete-volume** predictions and references, with the actual native spacing.

| Metric | Interpretation |
|---|---|
| Dice | `2*TP/(prediction_voxels + reference_voxels)`; overlap. |
| IoU | `TP/(prediction + reference - TP)`; stricter overlap scale. |
| Precision | Fraction of predicted primary-target voxels within the annotated target. |
| Recall | Fraction of reference target voxels recovered. |
| HD95 | 95th percentile of pooled bidirectional surface distances, millimeters. |
| ASSD | Mean of pooled bidirectional boundary-voxel distances, millimeters. |
| Surface Dice | Fraction of bidirectional boundary voxel centers within the fixed tolerance, default 2 mm. |
| Volume | Reference/prediction voxel count × physical voxel volume, in mL. |
| Relative volume error | `(predicted-reference)/reference`; undefined when reference is empty. |
| Complete miss | Positive reference with an empty prediction. |
| FP volume/components | Prediction outside the primary-target reference and components not touching it, under this annotation scope. |

**Surface convention:** 6-neighbor morphological boundary voxel centers, Euclidean distances with anisotropic spacing, pooled directions, **unweighted by surfel area**. These are not interchangeable with another paper's surfel-area-weighted normalized Surface Dice, per-direction-max HD95, or voxel-unit distances. Recompute all methods with one declared implementation for a fair table.

Surface computation crops to a union bounding box with a margin to bound distance-transform memory without dropping foreground. Metric masks themselves are not downsampled for plotting. Tolerance is prespecified via `--surface-tolerance-mm`; it is not chosen by reading test errors.

| Reference/prediction state | Policy |
|---|---|
| Positive, prediction empty | Dice/IoU/precision/recall zero; complete miss one; Surface Dice zero; HD95/ASSD null with `one_empty_infinite_distance`. |
| Both nonempty | Normal overlap and physical surface metrics. |
| Confirmed-negative reference, prediction empty | Dice/IoU/precision/recall and Surface Dice one by explicit convention; distances null with `both_empty`. |
| Empty reference, nonempty prediction | Dice/IoU/precision/recall and Surface Dice zero by explicit convention; distances null; FP volume/components retained. |
| Missing reference | Prediction route; no invented overlap/calibration metrics. |
| Technical failure | Recorded failure with reason; distinct from a valid complete miss. |

Aggregate distances summarize finite observations **with their counts**, alongside complete-miss and nonfinite-surface counts. They do not hide misses by presenting a favorable finite mean alone. Every eventual paper table should show these counts beside HD95/ASSD. JSON is strict: undefined values are null, not nonstandard `Infinity` or silent zeros.

Patient-level summaries average multiple cases within a patient before calculating mean, median, dispersion and bootstrap intervals. Confidence intervals use patient resampling, not millions of correlated voxels pretending to be independent patients.

## 28. Calibration, ROC/PR, and uncertainty limits

Each labeled evaluation saves a deterministic uniform sample of up to 20,000 **native-grid voxels per case**. The report takes a further bounded sample, normally up to 200,000 total voxels. Each retained voxel receives inverse inclusion weight `population_voxels/retained_count_in_case`.

This restores voxel-pool weighting across differently sized volumes rather than treating an artificially balanced foreground/background sample as natural prevalence. Sampling can still miss extremely small targets; ROC/PR is skipped if both classes are absent. Predictions remain correlated within patients, so these descriptive voxel curves are not patient-level cancer-diagnosis validation.

Brier score is the weighted squared membership error. ECE uses ten fixed equal-width bins. Reliability compares weighted mean predicted membership with weighted reference frequency. Background voxels can dominate these quantities; interpret them alongside foreground overlap, misses and surface error.

Risk/coverage ranks cases by mean sampled binary entropy and plots cumulative mean `1-Dice`. This is only a descriptive confidence ranking; broad background can make entropy poorly reflect small-target failure. It is not a clinically validated referral threshold.

Restricted attention probes recompute attention on at most 128 selected bottleneck tokens and average heads. Their normalization differs from the full-key attention operation. The caption states that limitation. No MC dropout or multi-checkpoint ensemble uncertainty is claimed.

How to interpret the common figures:

- Falling patch loss means the optimizer is fitting its sampled patch objective; it does not establish complete-volume generalization.
- Stable or declining full-volume validation Dice can reveal overfitting or insufficient context despite improving patch loss.
- Dice distributions and ranks expose difficult cases hidden by a mean. Small targets can have low Dice from modest boundary displacement.
- HD95 shows large-tail boundary errors; inspect miss/undefined counts alongside finite distributions.
- Recall/precision identify undersegmentation versus excess prediction under the primary-label scope.
- Volume scatter and Bland-Altman reveal size bias; good total volume can coexist with poor spatial overlap.
- FP/FN maps localize errors and can reveal geometric conversion faults before a sophisticated architecture is blamed.
- Spectral/gate plots describe learned feature behavior; a visually interesting gate is not evidence of improved accuracy.

Copy the **whole result folder** when sharing its report; thumbnails and samples use relative links. Reports referring to a separate preparation directory need that directory for future regeneration, but existing thumbnails can still be browsed if retained. Local artifacts contain case IDs; curate them appropriately before public release.

## 30. Actual architecture switches and progressive ablations

Direct flags:

| Flag | Actual change |
|---|---|
| `--no-multiscale` | Ordinary second residual block at E2/E3. |
| `--no-transformer` | Identity bottleneck instead of transformer blocks. |
| `--no-adaptive-fusion` | Three-source concatenation/projection instead of source/channel softmax. |
| `--no-wavelet` | Direct encoder skips unless spatial control selected. |
| `--no-decoder-conditioning` | Removes context projection from spectral gates. |
| `--no-acquisition-conditioning` | Removes descriptor MLP/input from gates. |

```bash
python lung_ct_segmentation.py ablate --manifest "prepared/nsclc/manifest.json" --splits "splits/main.json" --run "runs/ablation_seed42" --preset compact --preflight --seed 42 --max-epochs 200 --steps-per-epoch 100 --configs baseline multiscale transformer fusion wavelet decoder acquisition full constant-metadata shuffled-metadata spatial-gate one-window
```

This command explicitly requests twelve jobs and can take a long time. For a short infrastructure pilot, name only two configurations and explicitly reduce the budget. The program does not default to all twelve after normal training.

| Progressive name | Mechanisms |
|---|---|
| `baseline` | Two-source residual baseline, boundary off, deep supervision retained. |
| `multiscale` | Hybrid three-source concatenate decoder plus multiscale CNN; transformer/wavelets/conditioning/boundary off. |
| `transformer` | Add bottleneck transformer. |
| `fusion` | Add adaptive source/channel fusion. |
| `wavelet` | Add unconditioned wavelet refinement. |
| `decoder` | Add decoder conditioning. |
| `acquisition` | Add acquisition conditioning, boundary still off. |
| `full` | Full hybrid including boundary supervision. |

The baseline-to-multiscale step also changes the decoder source topology, so it is not a perfectly isolated multiscale-only effect. For causal attribution, use direct hybrid flags to hold the three-source topology fixed and toggle exactly one mechanism, plus capacity controls. The progressive sequence is a practical study scaffold, not proof of isolated attribution.

Resume an interrupted individual job with `train --run its_subdirectory --resume its_last.pt`; `ablate` itself does not resume a partially existing study root.

## 31. Compare completed models honestly

Evaluate each checkpoint on the same final partition and operating-point protocol, then:

```bash
python lung_ct_segmentation.py report --inputs "results/baseline_test" "results/hybrid_test" --output "results/paired_comparison" --manifest "prepared/nsclc/manifest.json" --splits "splits/main.json" --vector both
```

Comparison requires matching manifest/split fingerprints, partition, exact case/patient sets, target, threshold, postprocessing, surface tolerance/convention and overlap, with no technical failure exclusions. The first supplied evaluation is the reference for paired differences. Patients, not voxels, are bootstrapped.

The current strict comparison gate requires the **same numerical threshold**. If you tune different thresholds per model, the automatic paired plot will refuse them; compare both at a common prespecified threshold or implement/review a protocol-aware comparison extension explicitly rather than editing provenance to bypass the check.

Cost plots use measured inference time and recorded parameter counts. Different hardware, precision or patch sizes remain material confounders even if metric definitions match. Inspect `environment.json` and `protocol.json`; a plot cannot by itself enforce compute fairness.

External baseline integration is intentionally manual and reviewable: run official nnU-Net/ResEnc, Swin UNETR or another method under the same patient split and target, export native-grid probability/mask predictions, and evaluate them with exactly the same metric convention. This release has no generic external-prediction import command; do not fabricate a compatible JSON folder or label the in-house baseline “nnU-Net.” Add such an importer only with explicit identity/geometry/protocol validation and meaningful tests.

For a paper, include strong tuned baselines, repeated seeds, development folds, uncertainty, clinically relevant target-size subgroups, annotation variability and an audited external cohort. Parameter count, FLOPs, peak memory and runtime each answer different questions. FLOPs are not computed in this release and must not be invented from parameter counts.

## 34. Troubleshooting

| Symptom | Action |
|---|---|
| Help cannot run | Use a supported Python and inspect syntax/file integrity. Help should not require torch or imaging packages. |
| CUDA false | Confirm active interpreter, driver/GPU support, and torch accelerator build using the official selector; rerun doctor. |
| Large CPU job refused | Intended behavior. Use explicit CPU only for small debugging, otherwise fix CUDA. |
| OOM during preflight | Smaller patch/batch in a new run; compact preset, AMP and checkpointing; close other GPU jobs. No fit claim is guaranteed. |
| OOM later | Read failure record, preserve last checkpoint; do not silently resume with changed architecture. A new resource recipe is a new run. |
| Very slow preparation | Initial hashing, compressed reads, resampling, full-volume boundary distances and disk writes are real costs. Check SSD capacity/throughput. |
| Very slow training | Verify actual CUDA usage, disk IO, patch size and worker count. Start with zero workers; benchmark changes after correctness. |
| Windows worker/spawn errors | Keep `--workers 0` until tested; run the script rather than pasting its classes into an interactive cell. |
| Missing ROI | Use the actual exact primary ROI name shown in QC and confirm its semantics; do not substitute every available structure. |
| Misaligned CT/mask | Review source conversion/registration. Do not copy headers or resize arrays by shape alone. |
| Missing slices/gantry tilt | Strict raw route excludes unsupported geometry. Use an expert-verified conversion/policy, not blind stacking. |
| Empty positive mask | Check annotation presence, ROI and resampling. Missing annotation is not a confirmed negative. |
| Stale cache or changed cohort | Preserve the old run and prepare a new destination; do not hand-edit fingerprints. |
| NaN/nonfinite gradients | Inspect HU range, labels, precision and LR. The program stops rather than replacing errors with zeros. |
| Empty predicted mask | It can be a valid complete miss. Inspect loss/sampling/threshold; retain it in reported Dice and miss counts. |
| HD95 null | Check surface status: one empty mask or both empty masks have an explicit undefined/infinite-distance policy. |
| ROC/PR skipped | Both classes may be absent in the bounded sample, labels may be absent, or evaluation samples were not produced. No fake curve is substituted. |
| Feature figures skipped | Baseline/disabled modules, `--figure-cases 0`, no captured evaluation artifacts, or insufficient variable metadata. |
| Paired comparison refused | Check exact cohorts, target, split, threshold, overlap, postprocessing, metrics and technical failures. |
| Report has no patient results | Run `evaluate` on a completed checkpoint; `report` never starts inference for you. |
| Safe checkpoint load fails | Use the matching source and compatible torch version. Do not blindly disable safe loading. |
| Full self-test exits 2 | Required dependency groups are missing; read JSON. `--available-only` changes exit handling, not verification completeness. |

Unexpected internal exceptions can still occur because GPU/imaging paths were not executable during delivery. Preserve their tracebacks, environment/config records, and an appropriately de-identified minimal reproducer before changing the scientific method.

## 35. Research questions, limitations, and source attribution

The central hypothesis is that deeper decoder context and retained native acquisition geometry can help refine directional wavelet details in encoder skips, while adaptive multiscale fusion combines contextual sources. This should be tested against ordinary spatial gating and capacity controls, not asserted from a complicated diagram.

Architectural inspirations specified in the project prompt:

1. Peng et al., *Multispectral Object Detection via Edge-Enhanced and Frequency-Aware Fusion Network* (EFAF), IEEE JSTARS, 2026. DOI: [10.1109/JSTARS.2025.3648007](https://doi.org/10.1109/JSTARS.2025.3648007). Coarse/detail feature separation and frequency-aware refinement are inspirations; this is not an exact reproduction of its visible/infrared detector.
2. Zhang et al., *MSF-DET: Multiscale Spectral Fusion Detection Framework for Low-Light Object Detection in Urban Intelligent Transportation*, IEEE Sensors Journal, 2026. DOI: [10.1109/JSEN.2026.3670619](https://doi.org/10.1109/JSEN.2026.3670619). Adaptive source/scale fusion is an inspiration; RT-DETR detection heads are not imported into the segmentation target.

Related wavelet/transformer segmentation work, including **WaveFormer** and **SWAG-Net**, means that merely combining a DWT and a transformer is not enough to claim novelty. Conduct an updated primary-literature search before writing the contribution statement. This code makes no claim of priority over that literature.

Useful primary resources:

- [TCIA collection and dataset citation](https://www.cancerimagingarchive.net/collection/nsclc-radiomics/)

Major practical limitations: a single retrospective primary-target cohort; imperfect/protocol-dependent annotations; a coarse working spacing that may remove tiny structures; high 3D memory cost; no automatic body crop; no automatic acquisition planning; no complete general DICOM contour/SEG support; no external baseline importer; no ensemble, TTA, automatic stress study or FLOPs profiler; and unexecuted GPU/imaging code paths at delivery.
